Step 1: How Context Telemetry Is Stored (Waking Life)

Google BigQuery • agent_logs

During waking interactive chat, the InterviewAgent streams every user utterance and agent response directly to Google BigQuery via an asynchronous OpenTelemetry/REST sink. This ensures high-throughput, append-only audit trails without slowing down the user experience or writing unverified beliefs to production tables.

Architectural Implementation & Data Pipeline Schema SQL / BigQuery Schema 
CREATE TABLE `adk_agent_telemetry.agent_logs` (
  event_timestamp TIMESTAMP NOT NULL OPTIONS(description="UTC event arrival time"),
  session_id STRING NOT NULL OPTIONS(description="Episodic session scope"),
  user_id STRING NOT NULL OPTIONS(description="Long-term user identity"),
  agent_name STRING NOT NULL OPTIONS(description="Agent emitting event"),
  event_type STRING NOT NULL OPTIONS(description="USER_PROMPT or AGENT_RESPONSE"),
  message STRING OPTIONS(description="Raw message content or JSON payload")
)
PARTITION BY DATE(event_timestamp)
CLUSTER BY user_id, session_id;

The Waking State: When a user interacts with the system, the InterviewAgent engages in dynamic dialogue using Google ADK 2.0 and Gemini 3.5 Flash Lite on Vertex AI. 🌱 Why Biologically-Inspired Agent Memory?

In biological neuroscience, waking daytime experiences are buffered in temporary hippocampal memory before being consolidated into the neocortex during REM sleep.

We apply this exact pattern to autonomous LLM agents: attempting to write permanent beliefs during live chat slows down conversational UX and risks storing contradictory statements. By separating Waking Episodic Logs (BigQuery) from Crystalline Memory (Cloud Spanner) via an offline Dream Harvest, our agents prune noise, capture intent over a single session, track intent trajectories across multiple sessions, and achieve long-term coherence.

⚖️ Why BigQuery + Cloud Spanner Dual-Layer Storage?

Different stages of the agent lifecycle require fundamentally different database characteristics:

Google BigQuery provides high-throughput append-only ingestion for raw conversational traces (USER_PROMPT and AGENT_RESPONSE), enabling full auditability and BigQuery AI batch analytics.
Google Cloud Spanner provides multi-region ACID consistency with ultra-low latency (< 10ms) primary-key lookups, ensuring subagents can recall user preferences instantly without consuming LLM inference tokens.

🔍 SQL Queries & REM Prompts in Dream Harvest

For dreams in particular, our architecture executes structured SQL queries across both database tiers and invokes Gemini 3.5 Flash Lite with a strict JSON schema:

src/common/telemetry.py: Implements BigQueryTelemetrySink to ingest conversational events (USER_PROMPT and AGENT_RESPONSE) asynchronously into BigQuery table adk_agent_telemetry.agent_logs.
src/common/telemetry.py 
import datetime
import json
import logging
from google.cloud import bigquery

class BigQueryTelemetrySink:
    def __init__(self, table_id="adk_agent_telemetry.agent_logs"):
        self.client = bigquery.Client()
        self.table_ref = table_id

    def log_interaction(self, user_id: str, session_id: str, agent_name: str,
                        event_type: str, message: str, payload: dict = None):
        """Append waking conversational event row to Google BigQuery."""
        row = {
            "event_timestamp": datetime.datetime.now(datetime.timezone.utc).isoformat(),
            "session_id": session_id,
            "user_id": user_id,
            "agent_name": agent_name,
            "event_type": event_type,  # 'USER_PROMPT' | 'AGENT_RESPONSE'
            "message": message,
            "metadata_json": json.dumps(payload or {}),
        }
        # Stream row into BigQuery without blocking conversation thread
        errors = self.client.insert_rows_json(self.table_ref, [row])
        if errors:
            logging.error(f"BigQuery ingestion error: {errors}")

3. src/pipeline/bq_to_spanner_sync.py 
from google.genai import types
from src.common.config import get_config

class BqToSpannerSynchronizer:
    def sync_to_spanner(self, user_id: str, session_id: str) -> dict:
        # 1. Retrieve all raw waking logs from BigQuery
        logs = self.telemetry_sink.get_session_logs(session_id)
        
        # 2. Artificial REM Sleep: Ask Gemini to distill structured JSON beliefs
        dream_prompt = f"Analyze these waking logs and distill JSON beliefs:\n{logs}"
        response = self.genai_client.models.generate_content(
            model=get_config().model_name,
            contents=dream_prompt,
            config=types.GenerateContentConfig(
                response_mime_type="application/json",
                temperature=0.2,
            ),
        )
        
        summary = self._parse_json(response.text)
        # 3. Crystallize preferences into Google Cloud Spanner table
        self.spanner_client.write_preferences(user_id, summary["preferences"])
        return summary

-- Google Cloud Spanner Schema Definition (Vector Search Enabled)
CREATE TABLE UserPreferences (
    user_id             STRING(128) NOT NULL,
    preference_key      STRING(128) NOT NULL,
    preference_value    STRING(1024) NOT NULL,
    category            STRING(64) NOT NULL,
    confidence          FLOAT64 NOT NULL,
    embedding           ARRAY(768),
    updated_at          TIMESTAMP NOT NULL OPTIONS (allow_commit_timestamp=true)
) PRIMARY KEY (user_id, preference_key);

CREATE VECTOR INDEX UserPreferencesByEmbedding
ON UserPreferences(embedding)
OPTIONS (distance_type='COSINE');

# Python Client Transaction Mutation (src/common/spanner_client.py)
def write_preferences(self, user_id: str, preferences: list):
    def _mutate(transaction):
        mutation_rows = []
        for p in preferences:
            mutation_rows.append((
                user_id,
                p["preference_key"],
                p["preference_value"],
                p.get("category", "general"),
                float(p.get("confidence", 0.9)),
                p.get("embedding"),
                spanner.COMMIT_TIMESTAMP,
            ))
        transaction.insert_or_update(
            table="UserPreferences",
            columns=("user_id", "preference_key", "preference_value",
                     "category", "confidence", "embedding", "updated_at"),
            values=mutation_rows,
        )
    self.database.run_in_transaction(_mutate)
src/preference_agent/server.py: Implements the sub-10ms cache interception pattern. Before invoking any Vertex AI LLM inference, the API endpoint checks Spanner memory first. On a hit, it returns instantly!
src/preference_agent/server.py 
@api.post("/api/preference/query")
async def query_preference_agent(request: ChatRequest):
    start_time = time.time()
    
    # 1. Vector Similarity Lookup in Cloud Spanner (COSINE_DISTANCE < 10ms)
    matched_records = _multi_method_spanner_retrieval(
        user_id=request.user_id, prompt=request.prompt, client=spanner_client
    )
    
    if matched_records:
        latency_ms = round((time.time() - start_time) * 1000, 2)
        response_text = format_multi_fact_spanner_response(matched_records, latency_ms)
        
        # Return Spanner memory instantly (typically 4ms – 9ms)
        return {
            "response": response_text,
            "source": "SPANNER_CACHE",  # Zero LLM token cost
            "latency_ms": latency_ms,     # Verified < 10ms SLA
            "spanner_record": matched_records[0],
        }
    
    # 2. Fallback to full ADK 2.0 LLM reasoning only on cache miss
    return await _fallback_adk_runner(request)
